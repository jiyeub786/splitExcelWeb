# 엑셀쪼개기 (SplitExcel Web)

원본 엑셀 워크북을 지정한 값(지역, 부서, 동/호수 등)별로 걸러내어, 양식 파일 형태의 결과물 여러
개로 나눠 저장하는 웹 도구입니다. FastAPI 백엔드가 실제 Excel을 자동으로 구동해 필터→복사→
붙여넣기→저장을 처리하고, 브라우저에서 파일 업로드부터 진행 상황 확인, 결과 다운로드까지 전부
할 수 있습니다.

> ⚠️ **Windows + Microsoft Excel 설치 환경**에서만 동작합니다. (Excel COM 자동화를 사용하므로
> Linux/Mac이나 Excel이 없는 서버에서는 실행되지 않습니다.)

## 주요 기능

- **파일 업로드**: 드래그 앤 드롭 또는 클릭으로 원본파일/양식파일 업로드. 두 파일이 같으면
  "양식파일이 원본파일과 동일함" 체크박스로 업로드를 한 번만 해도 됩니다.
- **시트명 자동완성 + 범위 선택 뷰어**: 원본파일을 올리면 실제 시트 목록을 자동완성으로 제공하고,
  "선택" 버튼을 누르면 실제 데이터를 미리보면서 클릭·드래그로 복사 범위/붙여넣기 위치를 지정할 수
  있습니다. 셀 하나만 클릭한 뒤 Shift+클릭으로 먼 셀까지 바로 지정하거나, 드래그 중 화면 가장자리에
  닿으면 자동 스크롤되며, "마지막 행 확장" 버튼으로 열 범위는 유지한 채 시트의 실제 마지막 데이터
  행까지 한 번에 늘릴 수 있습니다. 미리보기는 [`python-calamine`](https://pypi.org/project/python-calamine/)
  기반이라 Excel을 띄우지 않고도 즉시 응답합니다(수십만 행짜리 파일도 수 초 내). 같은 파일을
  반복 미리볼 때 매번 재업로드하지 않도록 서버측 임시 캐시(토큰)도 사용합니다.
- **필터 열을 A/B/C 문자로 입력**: 복사 범위/붙여넣기 위치와 같은 방식으로, 분리 기준이 되는 열을
  숫자 대신 열 문자(A, B, C...)로 입력합니다.
- **분리 대상 목록 자동 추출 + 사전 검증**: 원본파일의 시트명 + 열을 지정하면 그 열의 고유값을
  자동으로 뽑아 분리 대상 목록에 채워줍니다(다중 행 헤더 대응을 위해 제외할 헤더 행 수를 지정할
  수 있음). "검증" 버튼으로 목록의 각 값이 실제로 그 열에 존재하는지 미리 확인해 오타를 걸러낼 수
  있습니다.
- **실행 전 자동 점검**: "작업 시작"을 누르면 시트명이 원본·양식 양쪽에 모두 있는지, 범위 문법이
  올바른지 자동으로 확인하고, 열려 있는 Excel 프로세스가 있으면 경고합니다. Excel을 띄우기 전에
  흔한 실수를 미리 잡아냅니다.
- **진행률 표시줄 + 대기열 위치**: 실시간 로그 스트림을 분석해 전체 대상 중 몇 건이 끝났는지
  표시하고, 대기 중이면 대기열에서 몇 번째인지도 보여줍니다.
- **Job 히스토리**: 이 서버가 실행된 이후 처리한 작업 목록을 상태(대기/실행 중/완료/오류/취소됨)와
  함께 보여주고, 완료된 작업은 zip 전체 또는 개별 결과 파일만 골라 다운로드할 수 있습니다.
- **실행 로그 복사/다운로드**: 로그를 클립보드로 복사하거나 텍스트 파일로 저장할 수 있습니다.
- **설정 저장/불러오기 + 자동 임시 저장**: 입력값을 JSON으로 다운로드해뒀다가 다음에 그대로
  불러와 재사용할 수 있고, 브라우저에는 최근 입력값이 자동으로 저장되어 새로고침해도 유지됩니다
  (파일 자체는 브라우저 제약상 저장되지 않아 다시 선택해야 합니다).
- **다크/라이트 테마 전환**: 헤더의 🌙/☀️ 버튼으로 전환할 수 있고 선택값은 저장되어 다음에도
  유지됩니다. 아직 테마를 고른 적이 없으면 OS 설정을 자동으로 따릅니다. 색상 토큰은 저장소 루트의
  `../design.md`(다크)와 `../design2.md`(라이트)에 문서화되어 있습니다.
- **설명서**: 헤더의 "설명서" 버튼으로 파일 올리기부터 결과 다운로드까지 처음 쓰는 사람도 따라 할
  수 있는 단계별 안내와 주의사항을 볼 수 있습니다.
- **저장소 자동 정리**: 서버를 시작할 때마다 7일이 지난 업로드/결과 파일을 자동으로 지웁니다.

## 설치 및 실행

> ⚠️ **`python` 명령어를 그냥 쓰지 마세요.** 이 PC에는 Python이 여러 버전 설치되어 있는데
> (3.7 / 3.8 / 3.13), PATH 순서상 `python`이 가장 오래된 Anaconda 3.7로 잡힙니다. `fastapi`,
> `pydantic` 등 최신 패키지는 3.7/3.8을 지원하지 않아 `pip install -r requirements.txt`가
> 실패합니다. 반드시 **`py -3.13`**(Windows Python Launcher로 3.13 지정)으로 venv를 만드세요.
> `py -0p`를 실행하면 이 PC에 설치된 Python 버전 목록과 경로를 확인할 수 있습니다.

```bash
cd splitExcelWeb
py -3.13 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt

# pywin32 설치 후 1회 필요 (win32com 관련 DLL 등록)
python .venv\Scripts\pywin32_postinstall.py -install

uvicorn app.main:app --reload --port 8000
```

브라우저에서 `http://127.0.0.1:8000` 접속.

이미 구버전 Python으로 `.venv`를 만들어버렸다면, 그 폴더를 삭제하고 위 명령으로 다시 만들면 됩니다
(`.venv`는 언제든 재생성 가능한 산출물이라 지워도 안전합니다).

## 사용 방법

1. **원본파일 / 양식파일** 업로드(드래그 앤 드롭 가능). 원본파일을 올리면 저장 명칭/일자가
   파일명과 오늘 날짜로 자동 채워집니다.
2. **저장 명칭 / 저장 일자** 확인·수정 (결과 파일명: `{명칭}_{순번}_{대상값}_{일자}.xlsx`)
3. **시트 작업 정의**: 시트명(자동완성) / 필터 열(A, B, C...) / 복사 범위 / 붙여넣기 위치를 행으로
   추가. 범위는 직접 입력하거나 "선택" 버튼의 미리보기 뷰어로 지정하고, ▲▼ 버튼으로 행 순서를
   바꿀 수 있습니다.
4. **분리 대상 목록**: 한 줄에 하나씩 직접 입력하거나, 원본파일의 열에서 "추출"로 자동 채우고
   "검증"으로 오타가 없는지 확인.
5. **옵션**: 줌 레벨, 눈금선 제거, 수식 경로 참조 제거 여부.
6. **작업 시작** 또는 **테스트(1건)**(분리 대상 중 첫 항목만 실행) 클릭. 시트명/범위 사전 점검과
   Excel 실행 여부 확인이 자동으로 이뤄집니다.
7. 실행 로그와 진행률, 대기열 위치가 실시간으로 표시됨(SSE). 로그는 복사하거나 파일로 다운로드
   할 수 있습니다.
8. 완료되면 **결과 다운로드** 버튼으로 zip 전체를 받거나, 아래 "Job 히스토리"에서 개별 결과
   파일만 골라 받을 수 있습니다.
9. 실행 중 **취소**(협조적 취소, 현재 시트 작업까지 마치고 중단) 또는 **강제 종료**(Excel
   프로세스 자체를 종료, 현재 작업만 멈추는 것이며 서버는 꺼지지 않음)로 중단 가능.
10. **다운로드/불러오기**로 입력값을 JSON 파일로 저장하고 재사용 가능(브라우저에도 최근 입력값이
    자동으로 남아있어 새로고침 후에도 이어서 작업할 수 있습니다).

막히는 부분이 있으면 화면 상단 **설명서** 버튼을 참고하세요.

## 폴더 구조

```
splitExcelWeb/
├── app/
│   ├── main.py            # FastAPI 앱, REST/SSE 엔드포인트
│   ├── job_manager.py      # Job 큐, 단일 워커 스레드, 취소/로깅/히스토리/저장소 정리
│   ├── excel_processor.py  # Excel COM 자동화(필터→복사→붙여넣기→저장) 핵심 로직
│   ├── preview.py          # 시트명/그리드 미리보기, 열 고유값 추출/검증, dry-run 검증
│   ├── file_cache.py       # 미리보기용 업로드 파일 임시 캐시(토큰 기반)
│   └── models.py           # 요청 스키마(Pydantic)
├── static/
│   ├── index.html
│   ├── app.js
│   └── style.css
├── storage/                 # (버전관리 대상 아님, .gitignore 처리, 7일 지나면 자동 정리)
│   ├── uploads/<job_id>/   # 업로드된 원본/양식 파일(런타임 생성)
│   └── results/<job_id>/   # 처리 결과 + <job_id>.zip(런타임 생성)
├── 개선아이디어.md          # 개선 아이디어 및 반영/보류 내역
└── requirements.txt
```

## 알려진 제약

- **동시성**: Excel COM 특성상 여러 요청을 동시에 안전하게 처리하기 어려워, 워커 스레드 1개가
  Job을 순차 처리합니다. 동시 사용자가 늘어나면 대기 시간이 길어질 수 있습니다(대기 중에는
  대기열 위치가 표시됩니다).
- **세션 환경**: 서버를 Windows 서비스로 돌릴 경우 인터랙티브 세션이 아니어서 Excel이 정상적으로
  뜨지 않을 수 있습니다. 일반 사용자 세션에서 `uvicorn`을 직접 실행하는 것을 전제로 합니다.
- **인증 없음**: 사내 전용 도구를 가정하고 있어 별도 인증/권한 처리는 포함하지 않았습니다.
- **Job 히스토리는 메모리 기반**: 서버를 재시작하면 초기화됩니다(디스크의 결과 파일 자체는
  7일간 남아있지만, 목록 화면에는 더 이상 표시되지 않습니다).
